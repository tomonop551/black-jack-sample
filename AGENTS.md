# Agent Guide

This file contains context for AI agents working on this project.

## Project Overview

This is a single-page Blackjack game built with [TanStack Start](https://tanstack.com/start). The entire game state lives in the browser. There is no backend persistence, authentication, or shared state. Betting chips and win/loss statistics persist in `localStorage`.

## Tech Stack

- **Framework**: TanStack Start (React + file-based routing)
- **Server State**: TanStack Query (queries/mutations over `localStorage`)
- **Runtime / Package Manager**: [Bun](https://bun.sh/)
- **Tool Management**: [mise](https://mise.jdx.dev/) via `mise.toml`
- **Build Tool**: Vite
- **Test Runner**: `bun:test`
- **Language**: TypeScript

## Development Workflow

Always use mise tasks instead of calling package managers directly:

| Task | Command |
| --- | --- |
| Install tools | `mise install` |
| Dev server | `mise run dev` |
| Production build + type check | `mise run build` |
| Run tests | `mise run test` |
| Preview production build | `mise run preview` |

Why not run `bun` directly? The `mise.toml` pins the Bun version and keeps the task definitions version-controlled, so every environment behaves the same.

## Coding Conventions

### Comments: explain "Why not"

Code comments should explain why an alternative approach was rejected, not merely restate what the code does. The code itself expresses *how*.

```ts
// Why not mutate the deck in place? Returning a new deck makes the game
// state predictable and easier to test.
export function shuffleDeck(deck: Card[]): Card[] { ... }
```

### Tests: describe "What"

Test descriptions state what behavior is being verified.

```ts
// What: a standard deck contains 52 unique cards.
describe('createDeck', () => {
  it('returns 52 cards', () => { ... })
})
```

### Commit messages: explain "Why"

Commit subjects follow conventional style. The body explains why the change was made.

```
feat: add dealer stand threshold

Why: Without a fixed threshold, the dealer action would be undefined,
leading to inconsistent game outcomes across reloads.
```

### Language

All comments, documentation, and commit messages are written in English.

## Testing

- Game logic lives in pure functions inside `src/lib/blackjack/`.
- Tests are co-located next to the modules they verify and run with `mise run test`.
- UI behavior is verified manually via `mise run dev`; keep logic testable without a browser.

## State Management

Round state (cards, phase, result) is local React state in `src/routes/index.tsx`; it is ephemeral and never persisted. The persistent player profile (chips, last bet, stats) is managed by TanStack Query, which treats `localStorage` as its async data source via the wrappers in `src/lib/profile/storage.ts`. Why not useState for the profile too? Query gives a single cache shared by every component and a mutation lifecycle, so persistence stays out of the UI code.

The `QueryClient` lives at module scope in `src/routes/__root.tsx` because all queries run client-side against `localStorage`; there is no per-request server data to isolate.

## Adding New Routes

TanStack Start uses file-based routing. Place new route files in `src/routes/`. Run `mise run dev` or `mise run build` to regenerate `src/routeTree.gen.ts`.

## Build Artifacts

Production builds are emitted to `dist/`. The directory is ignored by Git.
